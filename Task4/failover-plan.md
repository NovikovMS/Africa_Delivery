| Компонент | Резерв | Переключение | RTO | RPO |

## 3. Сценарии

### S-1. Отказ зоны в Кейптауне

- **Признаки:** RDS переключился на standby, задачи Fargate в одной зоне недоступны.
- **Решение:** автоматически. Дежурный проверяет, что всё переключилось.
- **Шаги:** RDS Multi-AZ сам переключается за 1-2 мин. ALB уводит трафик на задачи во второй зоне. Автомасштабирование добирает задачи.
- **Потери данных:** нет, репликация синхронная.

### S-2. Отказ региона Кейптаун или блокировка аккаунта AWS

- **Признаки:** burn rate 14,4x по SLO заказа ([observability.md](../Task3/observability.md)), синтетика из Лагоса не видит API, AWS Health подтверждает событие в регионе.
- **Решение:** CTO. Условие: AWS подтвердил событие в регионе или недоступны 2 зоны дольше 15 мин без прогноза восстановления в ближайшие 30 мин.

| Мин | Шаг | Кто |
|---|---|---|
| 0-5 | Подтвердить алерт, открыть инцидент, проверить AWS Health | Дежурный |
| 5-15 | Решение о переключении | CTO или руководитель инцидента |
| 15-20 | Зафиксировать последнюю реплицированную транзакцию в Cloud SQL | Дежурный |
| 20-30 | Остановить задачу Database Migration Service, промоутить Cloud SQL в primary | Дежурный |
| 30-40 | `terraform apply` с площадкой GCP: Cloud Run ядра и сервиса ПДн KE от 2 инстансов, очередь Pub/Sub | Дежурный |
| 40-45 | Сменить основной origin CloudFront на Cloud Run | Дежурный |
| 45-55 | Синтетика, тестовый заказ, проверка вебхуков M-Pesa и Flutterwave | Дежурный |
| 55-60 | Статус-страница, сообщение продавцам | CEO |

- **Потери данных:** до 5 мин транзакций. Платежи за это окно восстанавливаются из выгрузки транзакций партнёров, заказы сверяются вручную.
- **Подготовлено заранее:** IP Cloud NAT в GCP есть в списке доступа сервиса ПДн NG. Вебхуки партнёров идут через CloudFront, их адрес не меняется.
- **Обратно:** после восстановления AWS - обратная репликация GCP → AWS через AWS DMS, переключение ночью с окном 30 мин.

### S-3. Отказ зоны Лагос у Layer3

- **Признаки:** Circuit Breaker ядра к сервису ПДн NG открыт, ошибки и таймауты в метриках.
- **Решение:** руководитель инцидента по runbook после 10 мин недоступности. CTO информируется.
- **Пока сервис ПДн недоступен:** заказы нигерийцев принимаются по токену, отправления и SMS ждут в очереди (F-06).

| Мин | Шаг |
|---|---|
| 0-10 | Подтвердить: статус Layer3, проверка с ВМ в Абудже |
| 10-15 | Промоутить реплику PostgreSQL в Абудже |
| 15-20 | Распечатать OpenBao в Абудже: 2 ключа из 3 у CTO, DevOps-лида, DPO |
| 20-25 | Запустить сервис ПДн NG в Абудже |
| 25-30 | Переключить DNS `api-ng` на Абуджу, TTL 60 с. Очередь отправлений и SMS разбирается сама |

- **Потери данных:** до 1 мин изменений профилей и адресов. Заказы не теряются: они в ядре.
- **Обратно:** Лагос пересобирается как реплика Абуджи, переключение ночью.

### S-4. Layer3 недоступен целиком

- **Признаки:** обе зоны Layer3 недоступны дольше 1 ч или аккаунт заблокирован.
- **Решение:** CTO и DPO. Данные остаются в Нигерии, согласование юриста не нужно.
- **Шаги:**
  1. Поднять PostgreSQL и сервис ПДн на ВМ Lineserve из второго репозитория pgBackRest.
  2. Восстановить OpenBao из снимка, распечатать.
  3. Переключить DNS `api-ng`.
- **Потери данных:** до 5 мин изменений ПДн.

### S-5. Обрыв связи Нигерии с Кейптауном

Пример - обрыв кабелей WACS, MainOne, SAT-3 и ACE в марте 2024.

- **Признаки:** синтетика из Лагоса не видит API, из Кении всё работает.
- **Решение:** технического переключения нет: ядро одно, и оно вне Нигерии. CEO решает о сообщении, маркетинг ставит рекламу в Нигерии на паузу.
- **Что работает:** каталог из кеша CloudFront в Лагосе до 24 ч (stale-if-error, [ADR-002](../Task3/adr-002-caching-strategy.md)), приложение в офлайн-режиме. Заказы в Нигерии недоступны.
- **Потери данных:** нет.
- **Триггер:** обрыв дольше 4 ч повторился - выносим ядро для Нигерии в AWS Local Zone Лагос ([ADR-003](adr-003-data-residency.md), раздел «Обратимость»).

### S-6. Ошибочное удаление или порча данных

- **Решение:** CTO.
- **Шаги:** восстановить БД на момент до ошибки в новый экземпляр: RDS PITR для ядра, pgBackRest для ПДн NG. Сравнить и перенести затронутые таблицы.
- **Время:** 1-2 ч. Потери: только изменения затронутых таблиц после момента восстановления.
