# Реестр противоречий

**Версия:** 1.0
**Автор:** Solution Architect

В реестр включены только взаимоисключающие требования: выполнение одного делает невозможным выполнение другого. Трудности без второй стороны вынесены в риски Architecture Canvas.

Источники: 
- А1 - транскрипт кик-оффа
- А2 - маркетинговый бриф
- А3 - юридическое письмо
- А4 - список функций PM
- А5 - письмо CTO
- А6 - письмо CFO
- А7 - записка инвестора
- ЦБ - цели бизнеса в описании кейса.

## 2. Что физически невозможно одновременно

1. Запуск 15.10 и целевая платформа CTO (C-01).
2. Бюджет $5k/мес и active-active мультирегион под 10M пользователей (C-02).
3. 99,99% без деградации и критический путь через партнёров с меньшим SLA (C-09).
4. 6 контракторов и self-hosted Kafka, Istio, Oracle на трёх кластерах с дежурством 24/7 (C-03, C-04).

Из каждой пары выбираем одну сторону явно и фиксируем цену выбора.

## 3. Что не является требованием

| Формулировка | Источник | Почему не требование |
|---|---|---|
| «Как Amazon», «как Wildberries» | А1, А7 | Метафора, к тому же две разные модели. Проверяемого содержания нет |
| «Всё P0» | А4 | Отсутствие приоритизации. Автор уволился |
| Блокчейн-лояльность | А1, А4, А5 | Инвестор сам: «не к октябрю, но изучите». Идея в исследовательский бэклог |
| «1 мин = $12k» | А1, А7 | Оценка потерь. Вход для расчёта доступности, а не целевое значение |
| «Миллион покупателей в первый месяц» | А2 | Рекламный лозунг. Не нагрузочное требование |
| Сертификация CNCF | А5, ЦБ | CNCF сертифицирует дистрибутивы и специалистов, а не прикладные платформы. Переводим в проверяемые критерии Cloud Native |
| Бюджет $9k/мес | шаблон TCO | Снят CFO: цифра из презентации совету, включает маркетинг (А6) |
| Тёмная тема, колесо фортуны | А4 | Пожелания без влияния на первую покупку |
